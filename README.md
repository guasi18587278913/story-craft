# story-craft

把跟人和事有关的材料（帖子、复盘、采访录音、零散经历、身边人的事、一门生意怎么赚钱）写成适合短视频的故事口播或故事脚本；也用于给这类材料挑讲法、修改手里有原材料的人物故事稿。这是材料驱动的写作技能，不是小说生成器或 App；不把任务限定为纯口播、两分钟、成功结局、反转或固定分镜。

本仓库以导入时的完整私有技能快照为基础，包含入口、脚本、模板、故事卡、写法卡、方法快照与改稿手册。[导入记录](docs/repository-import.json) 保存当时与本机版本逐字一致的清单、指纹和验证记录，作为历史保留；后续修改不再声称与该导入快照或本机安装版逐字一致，差异以版本记录为准，现行流程从 [SKILL.md](SKILL.md) 进入。

## 入口与内容

从 [SKILL.md](SKILL.md) 开始，按五步处理：盘点素材、匹配卡片、构建写稿提示、审稿与修改、交付。

- [故事卡与写法卡目录](references/story-cards/index.md)：18张故事卡、44张写法卡。
- [工作表](templates/story-workbench.md)：看点和观众会先问的问题、候选、关键事实原句与限制、每段安排。
- [改稿流程](references/revision/index.md)：整篇初稿由八位手册审稿员和一位用意审稿员审核；局部修改按影响选组，写稿方统一取舍和修改。
- [脚本说明](references/script-usage.md)：读卡、估时、引号数字核对、首读和审稿命令。
- [外部首读说明](agents/first-reader.md)：实际送审范围、时机、预算和版本记录。

包含近期改进：影响理解关系的改动后复核；关键事实原句进入写稿提示；审稿意见区分“必须修、待核原文、可选增强”。

2026-10-30 维护更新：已采用可靠性／流程契约修补与三处文档归并；“成稿稳定更自然、更值得听”的质量目标仍未证明达成。完整结论、未解决事项与历史验证范围见[内容评估与维护记录](docs/maintenance-evaluation.md)，仅供维护时查阅，不加入每次起草的必读路线。

当前流程契约以 [SKILL.md](SKILL.md) 为准：沿用任务受众、知识范围、形式与长度；区分用户选择、作者受托决定、作者假设和待答选择；默认一稿，最终正文默认不超过两版，不自动扩成两看点×两长度；审查未完成与外发授权如实记录。

2026-10-29 更新（导入快照中的历史记录，非本轮新增；旧“两分钟／双长度回退”已由现行长度分支取代）：

- 没定长度时，先写初稿并测实际字数与估时；两分钟装不下，先缩小这篇要讲的范围，还装不下再问长度，或交完整版和两分钟版。
- 用意审稿员（第 10 位）按稿件实际承诺检查理解：可理解的潜台词和后文兑现的悬念允许保留；失败、未解决或未释怀的故事不强求成功、成长或方法总结。
- 定看点时，列出没读过原文的人会先问的问题和回答它们的原文位置，作为写稿时不能省的信息；分段时每段要么推进看点，要么回答这些问题。
- 素材清单的“看点”改成“看点候选”：十个方向只作检查提醒，只列材料撑得起的两三条，每条写清哪件事、谁在意、想知道什么、原文位置。
- 技能说明写明什么时候用、什么时候不用，和 media-script-review 划清边界；删掉重复和指向旧入口的说法；整篇被否时先分清是看点不对还是没讲明白。
- 写法卡要先说得出用在哪一段、改这段的什么、用哪条素材才配；分段计划每行写清用了哪张写法卡，整篇组织卡写它管的段落范围。起草时写人物特点或下评价，先用材料里撑得住的具体动作或细节。
- 声称“做成了、管用”时要求真实结果证据，结尾也可以落在动作、感受或未解决的问题上。
- 局部审稿用 `--scope local`，必须指定 `--groups` 和修改范围文件 `--changes`；按事实、表达、开头或结尾等修改类型选组，不默认九审。改后新引入事实或理解关系变化时，再按影响复核。
- 每轮审稿保存独立目录、送审输入与指纹；拒绝旧结果复用，缺少命令、启动失败、超时及异常会记入本轮汇总。
- 只挑讲法时先交“开场→经过→收束”和必要缺口；局部修改先给可替换正文，卡片核查和完整过程留工作记录。

## 安装与使用

仓库根目录就是技能目录。新环境可以将本仓库克隆到客户端使用的技能目录；例如本机 Codex 使用的路径：

```bash
git clone https://github.com/guasi18587278913/story-craft.git ~/.codex/skills/story-craft
```

目标目录已存在时，先检查已有内容再合并更新。Claude Code 也可以使用同一份技能目录；导入时没有修改本机已安装目录及其现有链接，后续仓库变更不自动同步到安装版。

调用示例：

```text
用 story-craft，把这份公开自述整理成故事口播。
保留事实与作者立场，未发生的结果不要补。
```

任务素材、草稿、审稿反馈和请求回执放在仓库以外的持久目录；脚本的任务目录参数使用绝对路径。

## 运行条件

- 辅助脚本使用 Python 标准库；“本机 Python 3.9 验证”是导入时的环境记录，不表示本轮重新验证了 Python 3.9。后续运行环境与检查结果按对应版本的验证记录区分。部分脚本依赖 `fcntl` 和 POSIX 信号，Windows 原生环境未适配。
- 跨模型审稿需要可用且已登录的 `codex` 或 `claude` 命令。`--prompts-only` 仅生成提示，不调用模型。
- 外部首读需要用户自己的 DeepSeek 凭据。脚本支持环境变量 `DEEPSEEK_API_KEY`、指定密钥文件或用户目录下的本地配置；完整顺序见 `run_first_reader.py --help`。仓库不包含凭据或登录态。
- 实时知识库通过 `gbrain_sc_media`／`sc-media-kb` 的只读 `get_page` 访问。本仓库包含已标来源的本地卡片与方法快照，不包含MCP服务或完整知识库；未实时查库时按技能规定说明。
- 音视频输入的转写依赖技能正文引用的 videocut 工作流，它没有打包进本仓库。纯文字流程可直接使用这里的文件。

## 检查

下面的命令检查本地结构、内容完整性与审稿脚本行为，不调用外部模型：

```bash
python3 -B scripts/check_integrity.py
python3 -B tests/test_reliability.py
```

`tests/test_reliability.py` 是现有受保护的离线回归入口，包含原 14 项与新增 66 项，共 80 项，并非删去或替换旧测例。既有 80 项通过记录对应 Linux／Python 3.12.13，不代表已验证 Python 3.9、macOS 或 Windows。

[导入记录](docs/repository-import.json) 中的“14 项离线回归、格式与完整性检查、独立审查和 4 个合成任务样例”属于导入时验证；同步时的逐文件指纹比对也只对应那份快照，不是本轮修改后的新验证。后续改动的验证范围、环境和计数分别记录，不沿用历史结果宣称当前通过。完整外部首读、跨模型审稿链路和真实观众效果不能由这些本地记录证明。

原句、数字的匹配和文件检查不能代替事实核验、写作质量判断或真实观众测试。外部首读和审稿需遵守各自范围与预算，不能将有文本返回等同于建议正确。

## 资料与配置边界

课程、书籍和示范稿保留原出处及引用边界。本仓库已公开；公开可见不等于为第三方内容授予开放转载许可，因此没有添加统一开源许可证。

知识库服务名和转写方式属于配置约定，不代表外发许可；当前用户／任务对具体服务和数据须有可核验授权并符合隐私与预算，不能把历史“长期授权”自动沿用到本次任务或其他账户。授权不明时先做本地工作，待授权部分停下，不自动公开临时链接。本次任务产生的稿件、个人聊天导出、密钥、模型回执及本机实验目录不随本仓库上传。

当前仓库与本机已安装技能是两个目录；后续编辑不会自动同步，也没有设置自动推送或CI。
